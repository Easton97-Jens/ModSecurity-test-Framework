## Motivation and problem statement

Generic all-case discovery admitted the native-only Reject source fixture with an intentionally empty expectation. The real matrix selector consequently failed before its cache-ownership checks. This change addresses that selector boundary, not cache ownership.

## Affected components and security boundaries

Only the dedicated NGINX YAML fixture, a new focused test and this paired record change. Generic expectation validation, native descriptors, canonical authority, Required selection, Parent and MRTS remain unchanged.

## Acceptance criteria

FORCE_ALL_CASES generic discovery excludes the native-only fixture. Other materializable cases remain discoverable. Null/true flag controls and direct validation remain strict. The same native case stays selected with its real descriptor; missing genuine evidence cannot PASS. Generated inventory remains unchanged.

## Alternatives considered

Restoring obsolete HTTP403/rule1100301 expectations or accepting arbitrary empty expectations would misrepresent the native contract. Broad selector or validator changes are unnecessary.

## Implementation decision

Set only `runtime_materializable: false` on the actual native source fixture. Existing generic applicability checks enforce the distinction even with FORCE_ALL_CASES. The native catalog route does not use this generic YAML executor flag.

- `tests/cases/connector-specific/nginx/phase4_body_reject.yaml`: explicit generic non-materializability.
- `tests/no_crs/test_native_reject_generic_discovery.py`: five focused checks for real all-case discovery, null/true controls, direct rejection, native selection and missing proof.
